# Сервер хранения цен криптовалют

REST API для отслеживания цен криптовалют через CoinGecko.

**Стек:** Python 3.12+, FastAPI, httpx, PyJWT, scrypt.
**Порт:** 8080. **Точка входа:** `cryptoserver.py`.

Все данные хранятся в оперативной памяти и удаляются при перезапуске.
База данных не требуется.

## Запуск

Из каталога проекта в Linux/macOS или Windows через WSL:

```bash
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -r requirements.txt
python cryptoserver.py
```

Запуск через скрипты:

```bash
chmod +x compile.sh execute.sh
./compile.sh
./execute.sh
```

Используйте один процесс сервера: данные в памяти не разделяются между workers.

## Документация API

- Swagger: http://localhost:8080/docs
- OpenAPI: http://localhost:8080/openapi.json
- Проверка работы: http://localhost:8080/health

Для защищённых запросов в Swagger получите токен через регистрацию или вход,
нажмите **Authorize** и вставьте токен без префикса `Bearer`.

## Конфигурация

Настройки читаются из переменных окружения. Для загрузки `.env` вручную:

```bash
cp .env.example .env
# Заполните необходимые значения в .env.
set -a
. ./.env
set +a
python cryptoserver.py
```

| Переменная | По умолчанию |
|---|---|
| `JWT_SECRET` | Случайный ключ на процесс |
| `JWT_TTL_SECONDS` | `3600` |
| `COINGECKO_BASE_URL` | `https://api.coingecko.com/api/v3` |
| `COINGECKO_API_KEY` | Пустая строка |
| `COINGECKO_KEY_HEADER` | `x-cg-demo-api-key` |
| `COINGECKO_CACHE_TTL_SECONDS` | `3600` |
| `HTTP_TIMEOUT_SECONDS` | `10` |

Если `JWT_SECRET` задан, его длина должна быть не менее 32 байт.
Сгенерировать ключ:

```bash
python -c 'import secrets; print(secrets.token_urlsafe(48))'
```

## API

Регистрация и вход принимают:

```json
{"username": "alice", "password": "your-password"}
```

| Метод и путь | Назначение |
|---|---|
| `POST /auth/register` | Регистрация, ответ `201` с токеном |
| `POST /auth/login` | Вход, ответ `200` с токеном |
| `GET /crypto` | Список отслеживаемых криптовалют |
| `POST /crypto` | Добавление: `{"symbol":"BTC"}` |
| `GET /crypto/{symbol}` | Текущая цена и сведения о криптовалюте |
| `PUT /crypto/{symbol}/refresh` | Обновление цены |
| `GET /crypto/{symbol}/history` | История цен |
| `GET /crypto/{symbol}/stats` | Статистика |
| `DELETE /crypto/{symbol}` | Удаление криптовалюты и истории |
| `GET /schedule` | Настройки автообновления |
| `PUT /schedule` | Изменение настроек |
| `POST /schedule/trigger` | Обновление всех отслеживаемых цен |

Все маршруты `/crypto` и `/schedule` требуют заголовка:

```http
Authorization: Bearer <token>
```

Тело запроса изменения расписания:

```json
{"enabled": true, "interval_seconds": 60}
```

Оба поля обязательны. Допустимый интервал — от 10 до 3600 секунд.

Ошибки возвращаются как `{"error":"..."}`:
`400` — некорректные данные, `401` — ошибка аутентификации,
`404` — ресурс отсутствует, `409` — дубликат,
`500` — ошибка поставщика или сервера.

## Особенности

- Список криптовалют и расписание общие для всех пользователей.
- Пароли хешируются с помощью scrypt, аутентификация использует JWT.
- Цены хранятся в USD как `Decimal`, временные метки — в UTC.
- История содержит максимум 100 последних наблюдений.
- Статистика рассчитывается по сохранённой истории.
- Изменение цены — последняя цена минус первая; процент — изменение / первая × 100.
  При первой цене 0 процент равен `null`.
- Автообновление включено по умолчанию с интервалом 30 секунд.
  Следующий запуск планируется после завершения предыдущей попытки.
- Ручное массовое обновление работает и при отключённом расписании.
- При ошибке массового обновления сохранённые цены и история не изменяются.
- CoinGecko может ограничивать частоту запросов. Перезапуск сервера
  не снимает ограничение поставщика.

## Тесты

Перед приёмочными тестами остановите работающий сервер:
тесты сами запускают и останавливают его на порту 8080.

```bash
make test              # Основные приёмочные тесты
make test SCHEDULE=1   # Приёмочные тесты с проверкой расписания
make test-unit         # Изолированные тесты без запросов к CoinGecko
make lint              # Проверка кода и форматирования
make format            # Автоисправление и форматирование
```

Приёмочные тесты зависят от доступности и лимитов CoinGecko.
Для частых локальных проверок используйте `make test-unit`.

`SCHEDULE=1` включает дополнительные тесты, а не автообновление сервера:
оно включено по умолчанию в обоих режимах.

## Docker

```bash
docker compose up --build
docker compose down
```

Compose использует `.env` для переменных, перечисленных в `compose.yaml`.
Для передачи остальных настроек добавьте их в раздел `environment`.
